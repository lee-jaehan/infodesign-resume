# infodesign-resume

디자인 강점과 개발 프로세스 이해, 장기간의 협업 경험을 보여주는 포트폴리오 웹사이트.

HTML·CSS·JavaScript로 제작한 정적 사이트다. 사용자가 제공한 Figma의 MAIN·WORKS·ABOUT 디자인을 구현했으며, 별도 설치나 빌드 없이 실행한다. GitHub Pages 공개를 위한 상대경로와 `.nojekyll` 설정을 포함한다.

## 구현된 화면

- MAIN: 학력, 2016~2026 활동 그래프, QUICK LOOK 연혁, 개발·디자인·뉴스레터·현재 관심 분야의 이야기
- WORKS: 외부 Notion 포트폴리오로 연결할 안내 화면. 현재 사용자의 요청으로 `https://google.com`을 연결했다. 실제 주소는 `index.html`의 `.works-link`에 있는 `href`만 교체하면 된다.
- ABOUT: 소속, 학교·개인 이메일, GitHub, Instagram 링크
- 공통: 최대 너비 1200px, 우측 고정 세로 메뉴, 페이드아웃 200ms → 페이드인 200ms, 페이지별 스크롤 위치 기억
- 모바일: 본문을 한 열로 재배치하고 그래프 내부에서만 가로 스크롤한다.

`#main`, `#works`, `#about` 주소로 바로 접속할 수 있다. 브라우저 뒤로·앞으로 이동을 지원하며, 운영체제의 동작 줄이기 설정에서는 전환 애니메이션을 생략한다.

디자인 원본: [Figma](https://www.figma.com/design/T4pE7eOp8X6LnKLsP0KJF5/Untitled?node-id=2-2). MAIN `2:2`, WORKS `13:83`, ABOUT `13:94`. A.SA. 제작부장 시작 월은 원본의 FEB 대신 사용자가 확정한 JAN을 적용했다.

## 기본 파일

- `index.html`: 페이지 구조와 CSS·JavaScript 연결
- `styles.css`: 화면 스타일
- `script.js`: 인터랙션
- `graph.js`: 활동 데이터, 달력 생성, 툴팁·키보드·다음 활동 탐색
- `graph.css`: 그래프와 말풍선 스타일
- `img/`: 사용자 제공 이미지와 Figma에서 추출한 원본 SVG
- `fonts/`: 로컬 Pretendard 글꼴과 라이선스
- `.nojekyll`: GitHub Pages에서 정적 파일을 그대로 제공하기 위한 설정
- `AGENTS.md`: 이후 개발 작업에 적용할 지침

## 로컬에서 확인

`index.html`을 브라우저에서 열면 사이트를 확인할 수 있다.

로컬 서버가 필요하면 프로젝트 폴더에서 다음 명령을 실행하고 `http://localhost:8000/`을 연다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

## GitHub Pages 공개 준비

프로젝트 최상위의 `index.html`을 진입 페이지로 사용한다. CSS·JavaScript는 상대경로로 연결해 프로젝트 사이트의 하위 경로에서도 동작하도록 한다.

저장소에 올린 뒤 GitHub의 Settings → Pages에서 Deploy from a branch를 선택하고, 배포할 브랜치와 `/(root)` 폴더를 지정하는 방식으로 공개할 수 있다. 현재 GitHub 저장소 연결과 실제 배포 설정은 아직 진행하지 않았다.

참고: [GitHub Pages 사이트 생성](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site), [공개 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 포트폴리오 구성 방향

목적은 팀의 아이디어를 시각적으로 구체화하고 개발 과정에서도 원활하게 협업할 수 있는 디자이너임을 전달하는 것이다. 디자인을 주된 강점으로 보여주고, 개발 이해도와 뉴스레터 협업 경험을 연결한다.

세 시기는 다음과 같다. 경계 월부터 다음 시기가 시작되는 방식으로 표현한다.

| 시기 | 사용자 제공 기간 |
|---|---|
| 개발자를 꿈꾸던 시기 | 2016년 ~ 2021년 3월 전환점 |
| 디자인 탐색기 | 2021년 3월 ~ 2025년 1월 전환점 |
| 현재 | 2025년 1월 이후 |

## 합의한 활동 그래프

- 전체 기간은 2016~2026년이다.
- 2016~2020년은 `2016–2020 · 축약`으로 표시한다. Visual Basic 활동은 6열 × 7칸의 작은 잔디 묶음으로 요약하고, 공백은 `//`로 줄여 표시한다. 묶음 전체를 하나의 활동으로 선택하며 말풍선의 기간은 계속 `2016년`이다. 요약 칸은 개별 날짜를 뜻하지 않는다.
- 2021년부터는 GitHub Contribution Graph 형태를 유지한다. 한 열은 한 주, 세로는 요일별 7칸이다. 축약 전보다 전체 가로 길이가 약 43% 짧다.
- 같은 날짜에 해당하는 활동은 같은 달력 칸에 연결된다. 설명에서 겹치는 활동을 함께 보여준다.
- 활동 시작·끝 구간은 진한 초록색, 중간 구간은 연두색으로 채운다.
- 연도만 있는 활동은 해당 연도 안에 약 6개월 길이로 표시하고 설명에는 연도만 적는다. ‘미상’이라고 표시하지 않는다. 6개월은 시각화용 대략적인 구간으로 관리하고 정확한 실제 기간으로 서술하지 않는다.
- 구현상 연도만 있는 활동은 1~6월에 배치한다. 월 단위 범위는 해당 월의 첫날부터 마지막 날까지 펼치고, 범위의 처음·마지막 7일은 진한 초록색으로 표시한다. 특정 월의 시작·입학 같은 사건은 해당 월을 진하게 표시한다. 이 일자들은 시각화 규칙이며 실제 활동 날짜로 단정하지 않는다.
- 중요한 사건은 별도 강조 표시를 할 수 있다. Visual Basic 입문과 첫 앱 디자인을 강조한다.
- 칸에 마우스를 올리면 작은 말풍선 형태의 툴팁을 띄운다. 모달이나 배경을 덮는 창으로 만들지 않는다.
- 말풍선은 활동 이름, 연도 또는 연도·월, 짧은 설명과 중요한 의미를 보여준다.
- 모바일에서는 탭으로 말풍선을 열고 바깥을 탭하면 닫는다. 키보드 포커스로도 설명을 볼 수 있게 한다.
- 그래프 영역만 가로로 스크롤한다. 설명이 스크롤 영역이나 화면 가장자리에서 잘리지 않게 한다.
- 화살표 버튼은 다음 활동의 시작점으로 이동한다. 방향키·Home·End로 달력 칸을 탐색하고 Enter·Space로 말풍선을 고정하거나 닫으며 Escape로 닫을 수 있다.
- 이전에 제안했던 ‘월별 열·활동별 행·높이 6칸’ 방식은 최신 합의에서 변경되었다.

## 에셋과 글꼴

사용자 제공 PNG는 기존 `img/` 파일을 그대로 사용한다. `img/figma/`의 로고, 화살표, 선은 Figma에서 추출한 SVG 원본이며 임시 다운로드 URL에 의존하지 않는다.

Pretendard Variable v1.3.9는 [공식 저장소](https://github.com/orioncactus/pretendard)의 배포 파일을 사용한다. SIL Open Font License 1.1 원문은 `fonts/OFL.txt`에 포함했다. 글꼴과 이미지 모두 로컬 파일로 제공한다.
